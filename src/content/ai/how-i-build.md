  text: "A lot of my week goes on work that repeats: writing tickets, turning notes into clear write-ups, keeping track of what's happening across email and calendar, and keeping side projects up to date. None of it is hard, but it adds up, and it pulls attention away from the parts of product work that need real thinking."

principles:
  - text: "Recurring work is a system problem, not an effort problem. If a task comes back every week, the fix is a process that runs itself, not me doing it faster."
    pending: true
  - text: "Different tasks need different context. Writing a ticket, drafting an article and building a web page each need their own inputs and rules. One general assistant would have to relearn them every time. Giving each area its own assistant keeps it focused."
    pending: true
  - text: "Handoffs are where quality leaks. When one assistant's output becomes another's input, the handoff matters as much as either assistant."
    pending: true
  - text: "Trust comes from not making things up. A document with one invented number is worse than one with an honest gap."
    pending: true
system:
  - text: "I organise my AI assistants into areas, and each one owns a recurring task."
  - text: "Work and writing. Assistants help me automate recurring tasks, organise and optimise my existing work, write tickets, and streamline workflows so they run more efficiently. A writing assistant helps with articles and portfolio case studies."
  - text: "Side project: this site. An assistant builds and maintains my portfolio site. It opened the GitHub pull request for v1."
  - text: "Daily newspaper. A personalised newspaper assistant pulls from my email and calendar every day."
  - text: "Finance. A private assistant keeps track of money."
  - text: "Building new assistants. A bot-designer assistant creates new assistants when a new area needs one."
  - text: "The assistants hand work to each other. For this site, the writing assistant sourced my case studies from my work email and Notion, then passed them to the site builder. It has one hard rule: if it can't verify a number, it flags it instead of inventing it. So every draft comes back with a short list of questions for me, not guesses."
outcome:
  - text: "My portfolio went from scattered Notion pages to a laid-out v1 site, and every case study says where each claim comes from."
  - text: "Any number that couldn't be traced is marked as unverified, so I know exactly what to confirm before anything goes public."
  - text: "The routine work runs in the background, and my attention goes to decisions and to people."
